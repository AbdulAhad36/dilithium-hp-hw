• Polynomial sampling can easily bottleneck performance
• Number Theoretic Transform accelerates polynomial multiplication,
  but is complex to implement efficiently
• Dilithium signature rejection may require multiple attempts to

Dilithium Performance Bottlenecks
Matrix by vector multiplication
   • Number Theoretic Transform (NTT) based multiplication improves
     performance but is still expensive
   • Matrix is sampled in NTT-domain, but input vector must be converted using
     the NTT and result must be converted back using Inverse NTT
Example: Matrix multiplication requires 𝑙 NTT transformations, 𝑘
inverse NTT transformations, k ∗ 𝑙 point-wise multiplications, and
𝑘 ∗ (𝑙 − 1) additions

Lessons Learned From Recent Work By Zhao et al
• Pipeline Operations
   • Passing polynomials directly between modules – less BRAM needed for
     intermediate results
• On-the-Fly Sampling
   • Re-sampling the A matrix for sign attempts – no need to stored entire
     matrix for multiple sign attempts
   • Enabled by a low-latency SHA-3 implementation rather than multiple slower
     instances
• Carefully Optimize Submodules
   • Lots of minor submodules are needed – their area adds up!

Conclusions
• Main Contributions:
   • Developed high performance Dilithium hardware architecture with publicly
     available code: https://github.com/GMUCERG/Dilithium
   • First FALCON implementation in hardware
• Observations:
   • FALCON is the optimal algorithm based on verify performance and
     transmission overhead
   • Dilithium is a strong all-around algorithm
   • Symmetric-based algorithm are slower and have larger transmission sizes,
     only the best from the perspective of maturity of security analysis
