## What the vectors are

The two files under `FIPS204_NTT/` are **FIPS 204-derived reference vectors**. They are not official standalone NIST NTT test files. The public ML-DSA ACVP material we located covers complete KeyGen, Sign, and Verify operations, so we cannot honestly call these inputs and expected outputs downloaded NIST NTT vectors. [FIPS 204](https://nvlpubs.nist.gov/nistpubs/FIPS/NIST.FIPS.204.pdf) defines the arithmetic; the [NIST ACVP ML-DSA specification](https://pages.nist.gov/ACVP/draft-celi-acvp-ml-dsa.html) describes the available full-operation testing. Complete official ML-DSA vectors belong in the later integrated signer/verifier stage.

The vectors use `q = 8380417`, `n = 256`, `zeta = 1753`, bit-reversed twiddle order, and coefficients in the normal `0..q-1` domain. `FIPS204_NTT/ntt_vectors.py` computes expected NTT, INTT, and pointwise outputs independently of the SystemVerilog golden model. Before writing vectors, it checks the staged butterfly formulas against direct evaluation at the odd powers of `zeta`, checks the inverse against the inverse evaluation formula, and checks NTT multiplication against a separate negacyclic schoolbook product. The random seeds are fixed; running `prepare` produces the same files each time. This validates the Python reference's conventions and internal consistency, though it is not a NIST certification of the RTL.

## Files and data path

| File | Purpose |
|---|---|
| `FIPS204_NTT/ntt_vectors.py` | The **one Python script**. `prepare` makes inputs and expected outputs; `compare` checks captured DUT outputs. |
| `FIPS204_NTT/ntt_inputs.txt` | 18 cases, each with a case ID, operation, and one or two 256-coefficient input polynomials. Generated and retained in Git. |
| `FIPS204_NTT/ntt_expected.txt` | Case ID, operation, and 256 expected coefficients per case. Generated before simulation and retained in Git. |
| `tb_uvm/tb_uvm_ntt_LightHD/tb_ntt_vectors.sv` | Reads the input file, drives the actual `ntt_engine` stream interface, and writes only observed outputs. For round trip and polynomial multiplication it chains actual DUT operations. It does not call the SV or Python reference. |
| `sim/ntt/run_uvm.do` with `NTT_MODE vectors` | Fast standalone capture mode; does not launch the full UVM regression. |
| `sim/ntt/ntt_dut_outputs.txt` | Observed DUT outputs, generated by the capture run. This file is ignored by Git and overwritten on each run. |
| `sim/ntt/vector.log` | Local Questa transcript containing capture and cycle-count messages; ignored by Git. |

The simple file format is `COUNT`, followed by `CASE <id> <operation>`, then `A` and optional `B` lines in the input file or one `OUT` line in the expected/observed files. Each coefficient is six hexadecimal digits. `ROUNDTRIP` means DUT NTT followed by DUT INTT; `MUL` means two DUT NTTs, DUT pointwise multiplication, then DUT INTT. Python compares case order, ID, operation, and every output coefficient. A missing file, malformed data, or wrong coefficient returns a nonzero exit code and prints `NTT COMPARE FAIL`.

## Run it yourself

From the repository root in PowerShell:

```powershell
py FIPS204_NTT/ntt_vectors.py prepare
Push-Location sim
& 'C:\questasim64_2024.1\win64\vsim.exe' -c -l ntt/vector.log -do 'set NTT_MODE vectors; do ntt/run_uvm.do; quit -f'
Pop-Location
py FIPS204_NTT/ntt_vectors.py compare
```

`prepare` creates the two files in `FIPS204_NTT/`; the Questa command drives the design and creates `sim/ntt/ntt_dut_outputs.txt`; `compare` reads the expected and observed files. The simulation's `NTT VECTOR CAPTURE COMPLETE` message only says capture finished. **The final `NTT COMPARE PASS` is the correctness result.** If the capture command fails, stop before comparison so an older output file cannot be mistaken for a new result. The SystemVerilog golden model remains in the main UVM bench. Run `do ntt/run_uvm.do` without `NTT_MODE vectors` in a fresh session for the full regression.

For a separate DUT capture file, use `compare --observed <path-to-output-file>`.
The default now points to the finalized design's capture file; no override is
needed for the commands above. Run details are in `sim/ntt/README.md`.
